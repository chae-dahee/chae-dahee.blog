## 데이터링크 계층 개요

두 장비 사이에서 직접 통신할 수 있도록 도움. LAN. 물리적 링크를 통해 연결된 두 장치 간의 효율적인 데이터 전송을 담당

물리계층에서 받은 비트를 묶어서 프레임으로 형성하고

동기화, 흐름 제어, 에러 검출을 제공

프레임 Frame : 일련의 비트로 구성

주요 개념, 프로토콜 : MAC address, Local Area Network, Ethernet(근거리 통신), Error Detection

MAC address : NIC에 장착됨. 통신 장치 간 중복 X. 물리적 주소 =/= IP는 (사설 IP처럼) 네트워크가 다르면 중복될 수 있음

### 데이터링크 계층 역할

- 한 노드(장치)에서 물리적으로 인접한 노드로 프레임을 전송, 통신 제어
- LAN 통신

LAN 밖(ISP 등 다른 네트워크)으로 전달하기 위해서는 network 계층을 통과해야 하는데, Local 상황에서의 통신은 데이터링크에서 통신을 할 수 있다.

### 노드, 링크, 프레임

노드 : 통신 기능이 있는 각각의 장치. 호스트, 라우터

링크 : 통신 경로를 따라 인접한 노드를 연결하는 선. 유선(물리적), 무선

프레임 : 데이터링크 기본 통신 단위 PDU

### 데이터링크 위치

모든 host(장치)에 존재한다 + 네트워크 장비(라우터, 스위치)

NIC or 칩에 구현 → 이더넷, Wi-Fi card, 칩 → 링크, 물리계층 구현

## 캡슐화와 프레이밍

### Encapsulation 캡슐화

상위계층에서 하위계층으로 전달될 때 발생

데이터를 Header 헤더, Trailer 트레일러로 감싸는 과정

**데이터 기본 단위 PDU(Protocol Data Unit)**에 따른 계층 캡슐화 과정

| 계층              | 데이터 기본 단위 | 최종                              |
| ----------------- | ---------------- | --------------------------------- |
| 애플리케이션 응용 | 메시지           | 메시지                            |
| 전송              | H/메시지         | 세그먼트(TCP) 유저데이터그램(UDP) |
| 네트워크          | H/세그먼트       | 데이터그램(패킷) IP               |
| 데이터링크        | H/데이터그램/T   | 프레임                            |
| 물리              | 프레임의 비트    | 비트                              |

헤더에는 source와 destination 주소 등 정보가 들어감

데이터링크 계층은 헤더(H)와 함께 트레일러(T, 오류 검출 비트)도 붙임

### Decapsulation 역캡슐화

반대 방향. 하위계층에서 상위계층으로 헤더를 떼어내는 과정

receiver에서 sender가 보낸 메시지(원본 데이터)를 확인하기 위해 계층별 헤더를 떼어 데이터를 변환한다.

각 계층에서 데이터는 해당 계층에 필요한 제어 정보, 헤더, 주소 등이 추가되고, 수신자에서는 이러한 정보가 하나씩 제거되어 원본 데이터를 얻을 수 있게 된다.

### Framing 프레이밍

데이터가 패킷(데이터그램) 상태인 것을 프레임이라는 논리적인 블록 단위로 나누고, 각 프레임에 Header, Trailer(캡슐화) 정보를 추가하는 과정

공유 매체인 경우 채널 액세스를 수행. 이더넷 케이블 등 여러 노드가 공유를 하는 경우(LAN 환경)

채널 액세스로 어떤 노드가 언제 데이터를 전송할지를 조정. CSMA/CD, CSMA/CA

헤더의 MAC 물리 주소 = 출발지 sender, 목적지(dest) receiver 정보

**flow control 송수신 속도 차이 컨트롤**

인접한 송수신 노드 간의 간격 조절, 데이터 과다 전송 방지

### sender 측

패킷(데이터그램)을 캡슐화해서 프레임으로 만듦

프레임에 오류 확인 비트(CRC), 순서 정보, 프레임 번호, 흐름 제어 정보 등 추가

이더넷 or 무선 물리 매체를 통해 프레임을 전송. receiver 호스트로 전송

### receiver 측

프레임 해석

오류 확인 비트(CRC), 순서 정보, 프레임 번호, 흐름 제어 정보 확인

decapsulation으로 헤더를 떼서 패킷(데이터그램)을 추출해서 receiver의 상위계층(네트워크 계층)으로 전송

## 오류 검출과 수정

### Error detection 오류 감지(트레일러)

신호 약화, 노이즈로 인한 오류 감지

1. sender가 오류 감지 코드를 receiver에게 제공한다
2. receiver는 데이터와 오류 감지 코드를 비교하여 오류를 감지하고, 프레임을 버리거나 **재전송 신호**를 보냄

ex. sender는 1101을 전송했는데 receiver에서 1001을 받으면, 이를 감지하고(error detection) 오류난 프레임 버림 or 재전송 요청 신호 보냄

감지만 할 뿐 오류 위치 파악은 불가. 위치 파악, 수정은 error correction 영역

**D** : 오류 검사로 보호할 데이터 비트. 헤더 필드도 포함 가능

**EDC** : Error Detection and Correction bits. 오류 감지 및 수정을 위해 추가하는 중복 비트(redundancy)

- EDC 필드가 클수록 감지, 수정 능력 높음. 대신 오버헤드 증가
- 오류 감지가 100% 보장되지는 않음. 감지 못하는 비트 오류가 드물게 존재

ex. sender는 D(데이터그램과 헤더)와 트레일러(EDC)를 보냄. 비트 에러가 자주 발생하는 링크를 지나가면, 나오는 프레임은 D’ EDC’이다. D’ 비트가 괜찮은지 EDC’으로 분석함. 맞으면 no error, 안 맞는 게 있으면 error

### Parity

**single bit parity** : 1의 개수가 홀수인지 짝수인지. (짝수 패리티 기준)

- **sender : 데이터의 1 개수가 홀수일 경우 parity bit는 1, 짝수일 경우 parity bit는 0** → 전체 1의 개수를 짝수로 맞춤
- 데이터 비트 8bits + 패리티 비트 1bit = 9비트
- receiver : count # of 1 → 짝수 ok, 홀수 error
- 홀수 개 비트 오류만 감지. 2개 비트가 동시에 바뀌면 감지 못함
- 컴퓨터가 1의 개수를 파악하는 방법 : XOR 연산

**Two dimensional bit parity** : 이차원 패리티 에러 디텍터

- 데이터를 행렬로 배치하고 행마다, 열마다 parity bit를 붙임
- 행렬로 XOR 연산. 행렬 패리티 연산 0일 경우 성공
- 단일 비트 오류는 틀린 행, 열이 만나는 위치로 찾아서 수정까지 가능

### CRC

**CRC** : Cyclic Redundancy Check 순환 중복 검사. 강력한 감지 코드. EDC + 패턴 방식

D(보내고자 하는 데이터 비트) + R비트 <D,R>

1. sender와 receiver는 r+1 비트 패턴 G(generator)를 미리 공유한다.
2. D비트를 왼쪽으로 r칸만큼 이동시킨다 XOR R 연산으로 R비트 정보를 추가한다. <D,R>이 G로 나누어떨어지도록(mod 2) R을 고름
3. receiver는 <D,R>을 G로 나눔 → 나머지 0이면 no error, 0이 아니면 error

`<D,R> = D * 2^r XOR R`

참고 : [네트워크 - Error Detection & Correction(2)](<https://junghyun100.github.io/Error-Detection-&-Correction(2)/>)

### Error correction 오류 수정

sender에게 재전송 요청 없이 receiver가 직접 에러 감지 및 수정 (FEC, Forward Error Correction)

오류 수정 코드 ex. 해밍코드, 2차원 패리티. (CRC는 감지 전용)

**재전송 요청 없이도 데이터 복구 가능 → 재전송 비용이 큰 무선, 위성 통신 등에 사용됨**

## Multiple Access Protocols 다중 접속 프로토콜

### Point to point, Broadcast

**Point to point** : 이더넷 스위치와 호스트 간 링크, PPP

**Broadcast** : 공유된 와이어, 예전의 이더넷(bus, hub)

Wi-Fi, 폰, 노트북, 위성 통신 등

### 왜?

단일 공유 broadcast channel → 간섭 발생

노드들이 동시에 두 개 이상의 전송을 하는 경우 → 간섭 발생

노드가 동시에 두 개 이상의 신호를 수신하는 경우 → 충돌 발생

분산 알고리즘 → 노드들이 채널을 언제(when), 어떻게(how) 공유할지 결정

### Channel Partitioning 채널 분할

통신 매체를 논리적으로 분할하고, 노드나 장치에 할당하는 방식

종류 : FDMA, CDMA, TDMA

#### TDMA : Time division

시간 구역 나눠서 역할마다 데이터 송신할 수 있음. length slot

고정된 slot(프레임) 길이를 사용, 가변 길이를 사용하면 slot 사이에 간섭 발생

할당된 시간 슬롯이 경과하면, 스위칭! 다른 사용자에게 할당되고, 정확한 타이밍에 동기화되어야 한다. 사용 안 하는 slot 상태 idle → 다른 노드가 쓸 수 없어 낭비

무선 통신 시스템. 휴대폰 통화(2G GSM)

#### FDMA : Frequency division

주파수 대역폭 슬롯을 사용해 분할. 라디오. 사용 안 하는 대역은 TDMA처럼 낭비

### Random Access 랜덤 액세스

노드들이 무작위로 통신 매체에 접근하는 방식

충돌을 감지하고, 발생할 경우 재전송 수행

Random Access Protocols > 유선 네트워크(이더넷), 무선 네트워크(Wi-Fi) 모두 사용

랜덤하게 접근 제어함. 노드 사이에 우선순위 없음. 사용 여부 확인

동시에 보내지면 → 충돌 발생. 복구 방법? 충돌을 감지하거나 ACK를 받지 못하면 재전송

재전송을 위한 랜덤 백오프 타임을 대기한다.

종류 : slotted ALOHA, CSMA, CSMA/CD, CSMA/CA

#### slotted ALOHA

랜덤한 데이터 송신 방식, 데이터링크 레이어에서 같은 시간(슬롯) 크기를 가진다.

노드들은 슬롯에 정확하게 동기화되어 있고, 동시에 보내지면 충돌 발생

슬롯 시작 부분에서만 전송 가능. 슬롯 내에서 충돌이 발생하면 데이터는 손실 → 다음 슬롯부터 확률 p로 재전송

확률 방식 사용. 최대 효율 약 37%(1/e)

#### CSMA

Carrier Sense Multiple Access. 다중 접속 프로토콜. 채널 감지

데이터 전송 전에 채널이 사용 중인지 확인. listen before talk

비었다고 생각하고 전송하는 동안, 채널이 사용되는 충돌 발생. 공간적 거리로 인한 전파 지연(propagation delay) 발생. 만나는 time에 충돌 발생

idle, busy, 보류, 계속 체킹

#### CSMA/CD +충돌 감지

운반 여부, 충돌 감지, 처리 → 즉시 전송 중지, 충돌 처리 VS 기존 CSMA는 충돌이 발생해도 프레임 전송을 끝까지 계속한다.

충돌을 감지하면 jam 신호를 보내고, binary exponential backoff만큼 대기한 뒤 재전송한다.

여러 노드가 공유 매체에 multiple 접속하는 유선 네트워크 이더넷

#### CSMA/CA +충돌 회피

무선(Wi-Fi)은 전송 중 충돌 감지가 어려워 충돌을 미리 회피

다른 device가 데이터를 전송하는 것을 감지한 경우 노드는 대기 상태에 머물며, 랜덤 백오프 후 다시 감지하고 전송 시도한다.

수신 노드로부터 ACK를 받아야 하고, 못 받았다면 다시 시도 or 충돌 회피를 위한 시간 조절한다.

RTS/CTS로 채널을 미리 예약하기도 함

### Taking Turns 차례 대기

노드들이 번갈아가며 통신 매체에 접근

순서, 우선순위에 따라

종류 : Polling, Token passing

#### Polling

**Polling 폴링** : master가 slave 노드들에게 차례로 전송 기회를 줌. 1:n

단점 : 폴링 시간 오버헤드, 불필요한 딜레이 타임, master에게 control 권한이 있고, 1:n 연결로 master 고장 시 전체 먹통

#### Token passing

**Token passing 토큰 패싱** : 토큰이 순환하는 방식. 노드 간에 토큰 전파. 토큰을 가진 노드만 전송. 순서 공정. 마스터 없음. 토큰 오버헤드, 대기 시간, 토큰 손실 또는 토큰 소유한(할) PC가 고장 나면 전체 전송 중단

## MAC 주소와 ARP

### MAC Media Access Control 주소

물리적 주소, LAN, 이더넷 주소. 16진수. 네트워크 인터페이스 카드 NIC 등 네트워크 장치에 할당됨, 데이터 프레임에 MAC 주소를 저장해 송신자와 수신자를 식별하는 데 사용됨

6바이트, 12개의 16진수 숫자

IEEE 공학 단체에 의해 관리됨. 생산자들이 주소 공간(앞 3바이트 OUI)을 구매해야 사용 가능. 이동성이 있다(다른 LAN으로 옮겨도 MAC 주소 유지).

MAC : 48bit ⇒ 2^48 ≈ 2.8×10^14 (약 281조)

IP : 32bit ⇒ 2^32 ≈ 4.3×10^9 (약 43억)

가지의 경우의 수를 가지고, IEEE가 제조사별로 할당하기 때문에 MAC 주소는 유니크를 가짐

LAN → 컴퓨터를 식별하기 위한 주소. 그룹 안에서는 유니크한 IP, MAC 주소를 가짐

### ARP

IP → ARP → MAC

ARP 테이블에 <IP 주소; MAC 주소; TTL>을 매핑함

TTL : time to live. 시간이 지나면 테이블 엔트리를 없앤다(보통 수 분).

데이터 프레임을 전송하며, IP 주소 일치하는지 브로드캐스트 메시지 전송

과정

1. **ARP 요청 전송** : 컴퓨터 A가 컴퓨터 B의 MAC 주소를 알고자 할 때, 컴퓨터 A는 ARP 요청 패킷을 브로드캐스트(목적지 MAC FF:FF:FF:FF:FF:FF)한다. ARP 요청 패킷에는 목표 IP 주소(컴퓨터 B의 IP 주소)와 송신 컴퓨터 A의 IP 주소, MAC 주소가 포함된다.
2. **네트워크 상의 모든 장치에 ARP 요청 수신** : ARP 요청 패킷은 브로드캐스트로 전송되므로 네트워크 내의 모든 장치가 이 패킷을 수신한다.
3. **목표 장치 응답** : 컴퓨터 B는 ARP 요청 패킷을 수신하고, 자신의 IP 주소와 일치하는 IP 주소가 있는지 확인한다. IP 주소가 일치하면 컴퓨터 B는 자신의 MAC 주소를 ARP 응답 패킷에 담아 컴퓨터 A에게 유니캐스트로 보낸다.
4. **ARP 응답 수신** : ARP 응답 패킷을 수신한 컴퓨터 A는 컴퓨터 B의 MAC 주소를 알게 된다.
5. **ARP 테이블 업데이트** : 컴퓨터 A는 이제 얻은 MAC 주소를 ARP 테이블에 저장한다. ARP 테이블은 IP 주소와 해당 MAC 주소를 매핑하는 엔트리들로 이루어져 있다. ARP 테이블은 이후 통신에서 목적지 장치의 MAC 주소를 빠르게 찾을 수 있도록 사용된다.

### LAN Addressing

**IP 출발지, 도착지 주소는 데이터그램 안에서 끝까지 유지되고,**

**MAC 주소는 LAN 안에서만 유효해 홉마다 프레임 헤더가 바뀐다. 다른 LAN으로 보낼 때 프레임의 destination MAC은 라우터 인터페이스의 MAC 주소다.**

과정

1. **MAC 주소 할당** : 각 LAN 장치는 고유한 물리적 MAC 주소(데이터 링크 계층 주소)를 가지고 있다. 이 MAC 주소는 네트워크 인터페이스 카드(NIC)에 할당되며, 장치가 제조될 때 고정적으로 설정된다.
2. **IP 주소 할당** : 각 LAN 장치는 네트워크 레이어에서 사용되는 IP 주소를 할당받는다. IP 주소는 논리적인 주소이며, 네트워크에서 라우팅 및 통신을 위해 사용된다.
3. **주소 관리 및 설정** : LAN 관리자 또는 DHCP(Dynamic Host Configuration Protocol) 서버를 통해 IP 주소 및 기타 네트워크 설정이 관리된다. DHCP를 사용하면 장치가 자동으로 IP 주소를 할당받을 수 있으므로 수동 설정이 필요하지 않다.
4. **데이터 송수신** : LAN에서 데이터를 보낼 때, 송신 장치는 목적지 장치의 IP 주소를 통해 목적지를 식별한다. 그러면 이더넷 프레임의 목적지 MAC 주소로 변환된다. 송신 장치는 목적지 MAC 주소를 ARP(Address Resolution Protocol)를 사용하여 파악할 수 있다. ARP를 통해 IP 주소에서 목적지 MAC 주소로의 매핑이 이루어진다.
5. **프레임 전송** : 송신 장치는 데이터를 목적지 MAC 주소를 가진 이더넷 프레임으로 패키징하고 네트워크 미디어(유선 또는 무선)로 전송한다.
6. **프레임 수신** : 수신 장치는 받은 이더넷 프레임을 열고 목적지 MAC 주소를 확인하여 데이터를 처리한다. 이후 데이터는 네트워크 레이어로 전달되어 해당 IP 주소를 사용하여 데이터를 처리하거나 다른 네트워크로 라우팅된다.

## 이더넷과 스위치

### Ethernet 이더넷 : Wired LAN

유선 LAN 많이 사용하는 프로토콜, 구현 간단, 저렴, 형태 진화, 초기 속도 10Mbps ~ 현대 속도 400Gbps

connectionless : handshake 안 함. unreliable : ACK, NAK 안 함.

이더넷 MAC 프로토콜 : CSMA/CD. 채널 상태 확인, idle일 때 사용, 충돌 체크. 반이중 공유 매체에서 사용. 스위치와 전이중으로 연결하면 충돌이 없어 사용하지 않음

물리적 토폴로지 연결 방식 과거 bus

현재 switch 데이터링크 레이어. switching device가 switch table을 보고 프레임을 해당 포트로 포워딩함

스위치는 데이터링크 계층 장치라서 프레임을 저장 후 전송(store and forward)하고, 포트 간 원활하게 통신한다. 호스트는 스위치의 존재를 모름. 투명함(transparent)

동시 여러 대 전송, 스위치를 사용하면 동시 통신 시 회선이 안 겹치면 충돌 안 일어남

### Flooding 플러딩

도착 MAC 주소의 포트를 모르니 브로드캐스트함

self-learning : 프레임이 들어오면 출발지 MAC 주소와 들어온 포트를 switch table에 기록. 목적지 A’의 response 프레임이 들어오면 A’의 포트도 switch table에 업데이트

데이터 송수신 과정에서 정보를 업데이트

과정

1. **데이터 프레임 도착** : 스위치가 한 포트로 데이터 프레임(패킷)을 수신한다.
2. **목적지 MAC 주소 확인** : 데이터 프레임은 목적지 MAC 주소를 가지고 있으며, 스위치는 이 주소를 확인한다.
3. **스위치 테이블 확인** : 스위치는 목적지 MAC 주소를 스위치 테이블과 비교하여 목적지 장치가 이미 스위치의 포트에 등록되어 있는지 확인한다.
4. **목적지 주소가 스위치 테이블에 없는 경우** : 목적지 주소가 스위치 테이블에 없거나 목적지를 식별할 수 없는 경우, 스위치는 입력 포트를 제외한 모든 포트로 데이터 프레임을 전송한다. 이것이 플러딩의 핵심이다.
5. **데이터 프레임 전송** : 스위치는 목적지를 모르는 상태에서 프레임이 들어온 포트를 제외한 모든 포트로 데이터 프레임을 전송한다.
6. **목적지 장치의 식별** : 데이터 프레임을 받은 장치는 프레임의 목적지 MAC 주소와 자신의 MAC 주소를 비교하여 자신이 목적지인지 확인한다. 아니면 프레임을 버린다.
7. **데이터 처리** : 목적지 장치는 데이터 프레임을 받아 상위 계층 프로토콜에 따라 처리한다.

모든 스위치는 각각의 테이블 정보를 가짐

기업은 여러 스위치를 다루는 대규모 네트워크를 가짐

### 스위치(데이터링크) VS 라우터(네트워크)

| 구분   | 스위치                      | 라우터                         |
| ------ | --------------------------- | ------------------------------ |
| 계층   | 데이터링크 계층             | 네트워크 계층                  |
| 주소   | MAC(forwarding)             | IP                             |
| 테이블 | switch table, self-learning | routing table, 라우팅 알고리즘 |

### VLAN 가상의 LAN

브로드캐스트가 많아지면, 과부하와 트래픽이 높아짐. 해결책으로 LAN을 여러 개로 가상으로 나눔.

브로드캐스트 도메인이 분리되어 보안 향상, 안정적

물리적 위치와 상관없이 다른 LAN에 있는 노드를 같은 VLAN으로 묶을 수 있음. 공간적 제약을 컨트롤함

또는 LAN을 분리해 놓은 것처럼 동작함. VLAN 간 통신은 라우터를 거쳐야 함

스위치가 여러 대일 경우, trunk port로 스위치끼리 연결. 802.1Q VLAN 태그로 프레임이 어느 VLAN 소속인지 구분
